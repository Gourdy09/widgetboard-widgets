# widgetboard-widgets

The community widget marketplace for [WidgetBoard](https://github.com/Gourdy09/widgetboard).

This repository defines how widgets are packaged and distributed, and hosts the registry WidgetBoard reads. It contains no application code, no authentication and no user data. A widget is an independent package: install it from the WidgetBoard admin board, no manual downloads.

| | |
|---|---|
| [`docs/WIDGET_SPEC.md`](docs/WIDGET_SPEC.md) | **The contract**: package format, manifest, lifecycle, settings, permissions, trust model, versioning, installation. Start here. |
| [`schema/`](schema) | JSON Schemas for `manifest.json` and `registry.json`. |
| [`examples/hello-clock/`](examples/hello-clock) | A minimal reference widget to copy. |
| `widgets/<github-username>/<name>/` | Published widgets, one folder per widget. |
| `registry.json` | The index WidgetBoard downloads. Generated by CI, not edited by hand. |
| [`tools/validate.mjs`](tools/validate.mjs) | The checks every submission must pass. |

## Submit a widget

1. Fork this repository.
2. Copy `examples/hello-clock` to `widgets/<your-github-username>/<widget-name>/` and edit the manifest (the `id` must be `<your-github-username>.<widget-name>`).
3. `npm install && npm run validate`
4. Open a pull request.

Automated checks only prove a package is well-formed. A maintainer reviews the code of every submission before it is merged.

## Naming Conventions

| Item | Convention | Example |
| :--- | :--- | :--- |
| **Folder** | lowercase, hyphenated | `ticker/` |
| **Manifest** | always `manifest.json` | `ticker/manifest.json` |
| **JavaScript entry** | descriptive widget name | `tickerWidget.js` |
| **Stylesheet** | matching widget name | `tickerWidget.css` |
| **Widget ID** | stable, unique identifier (`<username>.<name>`) | `gourdy09.ticker` |
| **Display name** | human-readable | Stock / Crypto Ticker |

## Develop the tooling

```sh
npm install
npm test           # schema, validator and registry tests
npm run validate   # validate every package and registry.json
```

Changing a rule? Update `docs/WIDGET_SPEC.md` and the schema, then regenerate the shared test vectors with `WRITE_CONFORMANCE=1 npm test`.
